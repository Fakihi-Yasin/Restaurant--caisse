# Restaurant POS — Project Rules

## Offline-first rules

The restaurant must keep working when the internet is down. The app is a PWA, tablet-first, and the main cash register device must work 100% offline: open the app, view the menu, create orders, send to kitchen ticket, take payments, close the day.

### Rules for all future code

1. The UI reads and writes to local storage first (IndexedDB via Dexie), never directly to the API.
2. Every write also goes into a local sync queue (status: pending / synced / failed). A sync service sends the queue to the API when the connection returns, one item at a time, with retries.
3. IDs are UUIDs generated by the client. The backend must be idempotent: if it receives an order with an id it already has, it returns the existing one instead of creating a duplicate.
4. The menu is downloaded from the server and cached in IndexedDB, so it stays available offline.
5. The app shell (HTML/JS/CSS) is cached by a Service Worker (vite-plugin-pwa), so the app can be reopened with no internet. The API itself is NOT cached by the Service Worker — the sync queue handles it.
6. Order numbers: the official sequential number is assigned by the server at sync time. Offline, the app shows a temporary local number. Do NOT change schema.prisma now — a `localNumber` field will be decided in step 3.
